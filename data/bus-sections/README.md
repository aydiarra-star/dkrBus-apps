# Portions de bus affichables, sans service daté

Cet extrait permet de répondre à une question limitée : **dans quel sens et par quelles rues la ligne est-elle cartographiée entre ces repères ?** Il ne permet pas de répondre « à quelle heure puis-je monter ? ». Les 17 repères sont sélectionnables dans *Trajet*, sous « Portions de bus cartographiées ». Aucun n’est ajouté comme arrêt de desserte au graphe voyageurs.

**Données et droits.** Coordonnées, identifiants, membres et sens de voirie : [© les contributeurs OpenStreetMap](https://www.openstreetmap.org/copyright), [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/). L’extrait réutilisable est dans [`busSectionWays.ts`](../../src/data/busSectionWays.ts) (13 ways, version, nœuds ordonnés, latitude/longitude WGS84) et [`busSectionReview.ts`](../../src/data/busSectionReview.ts) (nœuds des repères avec version et coordonnées, relation par sens). Les noms de présentation précisent le secteur ou le côté quand le nom OSM seul ne suffit pas. Les descriptions opérateur sont des références de recoupement, pas la source de la géométrie ni une autorisation de republier leur base. Aucune coordonnée, shape, minute de passage ou liste d’arrêts des ZIP historiques n’a été copiée dans cet extrait.

## Refaire les contrôles

1. Ouvrir le JSON **versionné** de la relation ci-dessus. Contrôler `route`, `ref`, opérateur, direction et rôle `platform` lorsqu’il existe. Exemple de vérification séparée : [way 108821782 v15](https://api.openstreetmap.org/api/0.6/way/108821782/15.json), [quai 4666430953 v5](https://api.openstreetmap.org/api/0.6/node/4666430953/5.json), [branche exclue aux Maristes](https://api.openstreetmap.org/api/0.6/way/649705992/3.json). Une version de relation fixe les IDs de ses membres, **pas** les versions ultérieures de leurs coordonnées : conserver l’extrait examiné ; un `/full` courant n’est pas un instantané historique.
2. [`compileBusScope`](../../src/routing/busGeography.ts) n’accepte qu’une chaîne simple : jointure par **même ID de nœud et mêmes coordonnées**, respect du sens unique, lecture des sommets de l’extrait dans l’ordre sans en supprimer ni combler un trou entre deux ways. Contrôle de saut à 300 m pour cet extrait (pas maximal entre sommets sources : 275,8 m). Un quai doit se projeter à ≤20 m sur la chaussée revue, à un chaînage strictement croissant ; une limite routière doit être le nœud même du way. Ces seuils détectent des erreurs ; ils ne prouvent jamais l’affectation d’une ligne à une rue.
3. `npx vitest run src/routing/busGeography.test.ts` vérifie les cinq portions, les deux chaussées, les trous, les 17 identités et les couples orientés. Pour essayer l’exemple des Maristes :

   ```sh
   npm run audit:place-connections -- --at 2026-11-18T19:00 \
     --from landmark:bus-osm-305375476 --to landmark:bus-osm-3403676386
   ```

   Résultat : `DOCUMENTED_SECTION_ONLY`, AFTU 40, 938 m, pas d’horaire. Inverser les IDs : pas de carte du 40. Remplacer les IDs par les coordonnées : un écart, même nul, est de la **proximité**, pas un accès. Le filtre sans marches exclut ces portions sans preuve d’accessibilité. Une portion ne crée ni arête pour le calcul daté, ni changement de véhicule, ni prix, ni durée de marche.
